### 这份数据的三个硬伤（先写在前面，不用等读者问）

1. **没有坐标**。10 078 行里一个经纬度都没有，只有「区县 + 片区 + 地址」文本。这是本项目最麻烦的地方，处理方式见下节。
2. **年份与特征不同期**。价格是 2017 年 8 月的挂牌均价，设施与住宅面来自 2026 年 11 月的 OSM 快照——中间隔了 9 年。处理方法：目标变量改用「**区内相对价**」（区县内 log 单价的 z-score），把城市级的水平漂移（含这 9 年的普涨）整体消掉，只留「同区之内谁比谁贵」这个空间结构。这一条不是装饰，是必须，否则 2017 的价格会被 2026 的地铁站解释出荒谬的系数。
3. **「暂无报价」占三成**。参考均价字段有 3 321 行是「暂无报价」，加「暂无信息」的建筑年代 3 266 行。价格缺失直接丢（不可插补，否则等于编数），属性缺失用同列中位数填并保留 `has_year` 标记。

## 二、如何把「没有坐标」变成「有坐标」

**没有用地理编码。** 链家/贝壳的小区详情页在本机访问会返 1.1 KB 的拦截页（实测 200 状态码但内容是验证页），高德/百度的地理编码 API 要 key。所以走的是另一条路：

> **名称关联**：用「小区名」当键，把价格挂到 W10 `geo-etl-pipeline` 里 1 181 个**有名住宅面**的质心上。

两轮匹配规则（`prepare.py`）：

| 轮次 | 规则 | 命中 |
|---|---|---|
| 1 | 名称归一（去括号、去空格、去「花园/苑/公馆/大厦」等通用后缀）后**精确相等**；同名多候选用「区县」消歧（跨区同名一律丢弃，不全凭就近猜） | 562 行 |
| 2 | 同一区县内「名称互相包含」且唯一命中，要求核心名长度 ≥4 | +87 行 |

得到的坐标是 **OSM 住宅面的几何质心**——真几何，不是猜的；代价是命中率只有 **9.6%**（649 / 6 757 个有价小区）。这个数不好看，但它诚实：宁可样本少，也不塞假坐标。

### 每一步丢了多少（`build/match_log.json` 原样对账）

| 步骤 | 行数 | 说明 |
|---|---|---|
| 原始表 | 10 078 | |
| 剔除「暂无报价」 | 6 757 | 丢 3 321，价格不可插补 |
| 名称关联命中 | 649 | 丢 6 108（6 078 无名可挂 + 21 同区多候选 + 9 跨区多候选） |
| 价格 1%–99% 分位裁剪 | 635 | 丢 14，区间 4 655–24 764 元/㎡ |
| 同一住宅面去重（取中位数） | 536 | 丢 99，一个 OSM 面被多个小区名命中时合成一个观测 |
| **区内样本量 < 20 的区县整区剔除** | **525** | 丢 11（新都 6、龙泉驿 5）。z-score 在 n<20 的区上不可信，宁可不做 |
| **最终样本** | **525** | 5 个中心城区、96 个片区 |

> 为什么敢丢新都、龙泉驿：这两个区只剩 11 个样本，区内的「均值/标准差」由 5–6 个数估计出来，后面的 z-score 和残差全都会被这两个数带歪。删除并记账，比留着好看。

## 四、目标变量定义（一句话版本）

```
price_per_sqm  →  log  →  在每个区县内做 z-score（均值/标准差只用训练折估计）
```

- 值域大致 ±2.5，1 个单位 = 该区县 1 个标准差
- R² 的含义因此是：**在同一个区里，模型能解释多少「谁比谁贵」的份额**，不含「这个区整体贵不贵」
- 折内估计（而不是全样本估计）是为了让测试折的均值/标准差从不进入训练信息

## 五、复现

```
python prepare.py     # 需要 ../geo-etl-pipeline/data/chengdu.db 在位
python features.py
python model.py
python figures.py     # 或直接 python run_model.py 一次跑完四段
```

随机种子全部固定为 42；`build/match_log.json`、`build/feature_log.json`、`build/cv_results.json` 是三个可复核的台账。
